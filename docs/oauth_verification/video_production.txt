emAIl Sentinel — OAuth Verification Video Script
=================================================

HOW TO PRODUCE THIS VIDEO
--------------------------
[ ] 1. Install OBS Studio (free, open source)
        sudo apt install obs-studio
        Set resolution to 1280x800 or higher.

[ ] 2. Record the session manually — the OAuth consent step requires a real human
        click through Google's consent screen (cannot be automated due to bot detection).

[ ] 3. After recording, auto-generate captions using Whisper (free, local, runs offline):
        pip install openai-whisper
        whisper recording.mp4 --output_format srt
        Then burn or embed the .srt into the video via OBS, DaVinci Resolve, or CapCut.

NOTE ON AUTOMATION:
  - Playwright/Puppeteer can automate most browser steps but NOT the OAuth consent screen.
  - AI video generators (Runway, Sora, etc.) produce synthetic screens — Google's
    reviewers need the real OAuth consent screen, so AI-generated video won't work here.
  - Arcade/Navattic/Storylane can produce polished walkthroughs but are simulated demos,
    not real OAuth flows.
  - Best path: record manually with OBS, add captions with Whisper.



Purpose: Demonstrate to Google's trust & safety team that the add-on's only Gmail
scope — gmail.addons.current.message.readonly — is used solely to read the one
message the user has open, only when the user clicks "Evaluate this email", and
that no data is stored externally or shared beyond Google's Gemini API and the
alert channels the user explicitly configures. No restricted scope is requested;
there is no background access.

Target length: ~2 minutes. No narration required, but on-screen captions help.
Record at 1280x800 or higher. Use your real Gmail account (not a test account) so
the OAuth consent screen appears exactly as users will see it.


PART 1 — INSTALL AND OAUTH CONSENT (30 seconds)
------------------------------------------------
BEFORE RECORDING: Uninstall emAIl Sentinel from your account so the consent screen
will appear fresh during the recording.
  - In Gmail, click the gear icon → "Manage add-ons" (or go to Gmail settings →
    Add-ons tab) and remove emAIl Sentinel, OR
  - In script.google.com → Deploy → Test deployments → Uninstall

THEN RECORD:
1. Open script.google.com and navigate to the emAIl Sentinel project.
2. Click "Deploy" → "Test deployments" → "Install".
3. Google's OAuth consent screen appears automatically — pause here for 2-3 seconds
   so reviewers can read it. It will show:
     - App name: emAIl Sentinel
     - Scopes requested: the Gmail current-message scope (Google words it roughly
       as "View your email messages when the add-on is running"; the scope ID
       gmail.addons.current.message.readonly is authoritative), plus Calendar,
       Sheets, Tasks, Docs, and external requests. Note there is NO whole-mailbox
       Gmail scope in the list.
   [NARRATOR: This is the OAuth consent screen users see when installing emAIl Sentinel.
   The only Gmail permission requested is the current-message scope — the add-on can
   read a message only while the user has it open and is interacting with the add-on.
   No whole-mailbox access is requested.]
4. Click "Allow". The install completes.
   [NARRATOR: The user grants permission. The add-on is now installed in their account.]
5. Open Gmail. The emAIl Sentinel icon appears in the right-hand add-on rail.


PART 2 — INITIAL SETUP IN SETTINGS (30 seconds)
------------------------------------------------
6. Click the emAIl Sentinel icon. The home card loads.
7. Click "Settings" (via the three-dot menu or nav button).
8. Show the Gemini API key field (already configured — the masked
   "Current key: ....XXXX" display is visible, showing the key is stored privately
   in Google UserProperties, not transmitted anywhere).
   [NARRATOR: The Gemini API key is stored privately in Google UserProperties — only
   the last four characters are shown. The key never leaves the user's own Google
   account except when making calls to Google's Gemini API.]
9. Scroll down briefly to show the SMS provider section (set to None) and the
   Google alert channels section (Chat spaces, Calendar, Sheets, Tasks, Docs).
   [NARRATOR: Alert channels are entirely user-configured. Here we can see SMS is
   disabled. Alerts can be sent via Google Calendar, Sheets, Tasks, or Docs — all within
   the user's own Google account.]
10. Click "Test Gemini". Toast appears: "Gemini OK — model responded."
    [NARRATOR: This confirms the Gemini API key is valid. The only external network
    call emAIl Sentinel makes is to Google's own Gemini API — no other third-party
    services receive any data.]


PART 3 — CREATE A RULE (20 seconds)
-------------------------------------
11. Navigate to Rules → "+ New rule".
12. Enter:
      Name: Video demo rule
      Rule text: Any email with SENTINEL_TEST in the subject line.
    [NARRATOR: Rules are written in plain English. This rule matches any email with
    SENTINEL_TEST in the subject line.]
13. Leave all alert channels unchecked (no SMS, no Chat — keeping it simple).
14. Click "Save". Toast: "Rule saved."
    [NARRATOR: The rule is saved to the user's own Google UserProperties — no
    external database or server is involved.]
15. Rule appears in the list with ON status.


PART 4 — NO ACCESS WITHOUT AN OPEN MESSAGE (10 seconds)
--------------------------------------------------------
16. Go back to the Gmail inbox LIST view (no message open). Open the add-on panel.
17. Only the home card renders — there is no button or path that reads any message
    from here. Pause for 2-3 seconds.
    [NARRATOR: From the inbox view, the add-on cannot read anything. It has no
    whole-mailbox permission — Gmail access is only possible on a message the user
    opens, and only when they explicitly ask for an evaluation.]


PART 5 — SEND TEST EMAIL AND EVALUATE IT (30 seconds)
-------------------------------------------------------
18. Open Gmail Compose.
19. Address it to your own Gmail address.
20. Subject: SENTINEL_TEST — video demo
21. Body: (leave blank or type anything)
22. Send. Wait ~10 seconds and open the arrived email.
    [NARRATOR: We send a test email to our own address using the trigger phrase in
    the subject line, then open it.]
23. With the email open, the add-on panel shows the contextual card with the
    "Evaluate this email" button. Pause for 2 seconds before clicking.
    [NARRATOR: With a message open, the add-on offers to evaluate it. Nothing has
    been read yet — Gmail access happens only when this button is clicked.]
24. Click "Evaluate this email". The button shows a spinner while Gemini evaluates.
25. The "Evaluation result" card appears: green "✅ 1 of 1 rule matched." banner and
    a "✅ Match — alerts sent" row for "Video demo rule" with Gemini's reason.
    [NARRATOR: The add-on reads the open message, sends the sender, subject, and a
    body excerpt to Google's Gemini API for evaluation, and shows the per-rule
    result. One match is found.]


PART 6 — SHOW THE ACTIVITY LOG (20 seconds)
--------------------------------------------
26. Click "View activity log" on the result card (or Activity log from the menu).
27. The log shows:
      - Evaluating open email — From: [your address] | Subject: SENTINEL_TEST...
      - Evaluating against rule "Video demo rule"...
      - MATCH! [Gemini reason]
28. Pause here for 3-4 seconds. This is the key frame for reviewers — it shows
    exactly what current-message data is accessed (sender, subject, body excerpt)
    and that it goes to Gemini for evaluation only, with the result logged privately
    in the user's own Google account (UserProperties).
    [NARRATOR: This is the complete picture of how the current-message scope is used.
    The add-on reads the sender, subject, and a body excerpt of the one open message —
    sends that to Google's Gemini API for rule evaluation — and logs the result here
    in the user's own Google account. No email content is stored externally or shared
    with any third party, and no other message was ever accessed.]


PART 7 — CLOSE OUT (optional, 10 seconds)
-------------------------------------------
29. Navigate to Help (three-dot menu → Help) → "Settings & troubleshooting".
30. Show the "How evaluation works" / Privacy text briefly — it states the add-on
    reads only the email the user has open, on demand, and that content goes only
    to Gemini and the user's configured alert channels.
    [NARRATOR: The built-in Help confirms the data-handling posture: the add-on reads
    only the email you have open, only when you ask, and content goes only to Google's
    Gemini API and the alert channels you configure.]
31. End recording.


KEY POINTS TO MAKE VISIBLE ON SCREEN
--------------------------------------
- The OAuth consent screen (Part 1, step 3) — no whole-mailbox Gmail scope listed
- The masked API key display — shows credentials stay in UserProperties
- The inbox list view with no evaluate capability (Part 4) — proves no background
  or whole-mailbox access exists
- The "Evaluate this email" button on an open message (Part 5, step 23) — the
  explicit user action that gates all Gmail access
- The Activity log evaluation entry (Part 6, step 27) — the clearest demonstration
  of what the current-message scope is used for
- "Gemini OK — model responded" toast — shows the only external call is to Google


WHAT NOT TO SHOW
-----------------
- Do not show your actual API key value
- Do not show your full phone number if SMS is configured
- Do not show any real sensitive emails in your inbox during scrolling
