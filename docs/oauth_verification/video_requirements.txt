emAIl Sentinel — OAuth Verification Video Requirements
======================================================

PURPOSE
-------
Demonstrate to Google's trust & safety team that the add-on's only Gmail scope —
gmail.addons.current.message.readonly — is used solely to read the ONE message the
user currently has open, only when the user explicitly clicks "Evaluate this email",
and that no data is stored externally or shared beyond Google's Gemini API and the
alert channels the user explicitly configures. There is no background access of any
kind, and no restricted scope is requested.


RECORDING REQUIREMENTS
-----------------------
- Duration: ~2 minutes
- Resolution: 1280x800 minimum (higher is fine)
- Account: Must use a real Gmail account — not a test account — so the OAuth consent
  screen appears exactly as users will see it
- Narration: Not required. On-screen captions are helpful but optional.
- Format: Standard video file suitable for upload to Google (MP4 preferred)


RECOMMENDED TOOLING
--------------------
- Screen recorder: OBS Studio (free, open source)
    sudo apt install obs-studio
- Caption generation (optional): Whisper (free, runs locally)
    pip install openai-whisper
    whisper recording.mp4 --output_format srt
  Embed the .srt via OBS, DaVinci Resolve, or CapCut.

AUTOMATION LIMITATIONS
-----------------------
- The OAuth consent screen cannot be automated (Google bot detection blocks it) —
  that step must be performed manually.
- AI video generators produce synthetic screens and will not satisfy Google's
  requirement for a real OAuth consent screen demonstration.
- Playwright/Puppeteer can drive the browser for non-OAuth steps but cannot replace
  the full manual recording.


CONTENT REQUIREMENTS
---------------------
The video must cover these key demonstrations, in order:

1. INSTALL + OAUTH CONSENT
   - Show the Google OAuth consent screen for emAIl Sentinel
   - Pause on the consent screen long enough for reviewers to read it (~2-3 seconds)
   - Consent screen must show: app name "emAIl Sentinel", and all requested scopes.
     The Gmail entry is the current-message scope (worded by Google roughly as
     "View your email messages when the add-on is running" — the scope ID
     gmail.addons.current.message.readonly is authoritative), plus Calendar,
     Sheets, Tasks, Docs, and external requests. There is NO whole-mailbox scope.
   - Complete the install by clicking Allow

2. SETTINGS — API KEY STORAGE
   - Open the Settings card
   - Show the masked API key display ("Current key: ....XXXX")
   - Demonstrates that credentials are stored privately in Google UserProperties

3. SETTINGS — ALERT CHANNELS
   - Scroll to show SMS (set to None) and Google alert channels section
   - Demonstrates that alert channels are user-configured and Google-account-based

4. TEST GEMINI CALL
   - Click "Test Gemini"
   - Show the "Gemini OK — model responded" toast
   - Demonstrates that the only external network call is to Google's own Gemini API

5. CREATE A RULE
   - Create a rule (Name: "Video demo rule",
     Rule text: "Any email with SENTINEL_TEST in the subject line")
   - Leave alert channels unchecked
   - Save the rule; show it in the list with ON status

6. SHOW THE INBOX LIST VIEW — NO ACCESS WITHOUT AN OPEN MESSAGE
   - From the inbox list view (no message open), open the add-on panel
   - Show that only the home card renders — there is no way to read or evaluate
     any message from here
   - Demonstrates: the add-on has no whole-mailbox capability; it cannot act on
     mail the user hasn't opened

7. SEND TEST EMAIL + EVALUATE THE OPEN MESSAGE
   - Compose and send an email to your own address with subject:
     SENTINEL_TEST — video demo
   - Open that email in Gmail
   - The add-on panel shows the contextual card with the "Evaluate this email"
     button — pause briefly: Gmail access happens ONLY when this button is clicked
   - Click "Evaluate this email"
   - Show the "Evaluation result" card: green "✅ 1 of 1 rule matched." banner and
     the per-rule "✅ Match — alerts sent" row with Gemini's reason

8. ACTIVITY LOG — KEY FRAME
   - Open Activity log
   - Show the evaluation entry: sender, subject, "Evaluating against rule ...",
     MATCH result
   - Pause here for 3-4 seconds — this is the primary evidence frame for reviewers
   - Demonstrates: what current-message data is accessed (sender, subject, body
     excerpt), that it goes only to Gemini, and that results are logged privately
     in the user's own Google account

9. HELP / PRIVACY (optional)
   - Navigate to Help → Settings & troubleshooting → privacy statement
   - Briefly show the privacy posture text ("reads only the email you have open...")


DO NOT SHOW
-----------
- Your actual API key value
- Your full phone number (if SMS is configured)
- Any real sensitive emails in your inbox during scrolling


KEY FRAMES FOR REVIEWERS
-------------------------
These moments must be clearly visible and unhurried:
- OAuth consent screen (step 1) — no whole-mailbox scope listed
- Masked API key display (step 2)
- "Gemini OK" toast (step 4)
- The inbox list view showing no evaluate capability without an open message (step 6)
- The "Evaluate this email" button on an open message (step 7) — the explicit
  user action that gates all Gmail access
- Activity log evaluation entry (step 8)
